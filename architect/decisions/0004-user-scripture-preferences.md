# ADR-0004: Пользовательский выбор Писания

- Статус: Частично заменено ADR-0005 (пункт 4)
- Дата: 2026-08-27
- Участники: владелец продукта, разработчик, QA-куратор
- Частично заменяет: ADR-0003, пункт 8

## Контекст

После внедрения серверного подбора приложение всегда запрашивало русский
Синодальный перевод. Владелец продукта решил дать пользователю тот же зависимый
выбор языка, перевода и чтеца, который используется в BibleGarden iOS. Само
воспроизведение озвученной цитаты будет реализовано отдельно.

## Решение

1. Загружать языки из `GET /api/languages`, а активные переводы вместе с `voices`
   из `GET /api/translations?language={alias}&only_active=1` той же Bible API.
2. Считать выбор зависимой тройкой `language → translation → voice`. При смене
   родителя очищать дочерние значения и разрешать сохранение только полной тройки,
   существующей в текущем каталоге.
3. Хранить тройку одним JSON-значением `meta.scripture_preferences`, включая
   стабильные числовые коды перевода и голоса и отображаемые подписи.
4. Для существующих и новых установок без сохранённого выбора оставить прежний
   дефолт `ru`, translation `1`, voice `1`; не менять его скрыто по локали устройства.
5. Фиксировать язык и перевод при входе в молитвенную сессию. Все запросы и
   prefetch этой сессии используют один снимок настроек. Код голоса пока только
   сохраняется для будущего аудио.
6. Offline fallback фильтровать по языку и переводу текущей сессии. Существующую
   passage-centric семантику истории и избранного по `canonical_id` не менять.

## Рассмотренные варианты

### Сохранять каждый список независимо

Отклонено: между тремя SQLite-записями запрос мог бы прочитать несовместимую
комбинацию языка, перевода и голоса.

### Применять изменение к уже идущей сессии

Отклонено: готовый prefetch и навигационный след могли бы смешать переводы.
Новая настройка применяется со следующего входа в сессию.

### Выбирать дефолт по системному языку

Отклонено для миграции: это незаметно изменило бы поведение существующих
установок. Пользователь меняет перевод явно на экране настроек.

## Последствия

- Экран настроек требует доступного каталога для изменения тройки; сохранённый
  выбор и основной поток остаются доступны при временной ошибке каталога.
- API может добавлять новые языки, переводы и голоса без выпуска клиента.
- Удалённый из каталога сохранённый ID не предлагается как валидный выбор.
- Воспроизведение голоса сможет использовать сохранённый `voiceCode` без миграции
  формата настройки.
- Кэш по-прежнему хранит один последний snapshot на `canonical_id`; это сохраняет
  прежнюю модель, а фильтрация не допускает выдачу другого языка offline.
