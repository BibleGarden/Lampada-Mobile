# Floating keyboard action visibility — 2026-10-09

Application source: `d02810b`; version reservation: `301ebf7`.
Android Release 1.3.30 and iOS Release 1.3.31 use the normal test API from `.env.local`.

## Repair and corrected expectation

The preceding report `2026-10-09-floating-keyboard.md` checked the first repair:
zero-height Samsung floating frames no longer expanded the goal to the window
bottom. Its expected behavior incorrectly left duration and Next visible behind
the floating panel. The owner caught the remaining overlap on the physical phone.
That earlier result does not establish acceptance of action visibility.

`useKeyboardLayout` now exposes keyboard visibility separately from occupied
height. A shown zero-height frame is `{ visible: true, top: null }`; only a hide
event makes visibility false. Setup keeps its usual field size for floating mode,
hiding duration and Next visually, from touch handling and accessibility until
the keyboard closes. Reflection also hides completion and return actions, while
its floating input keeps the normal layout. Positive-height docked frames retain
the existing input expansion. Text is preserved across hide and mode changes.

The corrected physical Maestro flow asserts that duration and Next are absent
both before and after typing, and return only after dismissal. Unit tests cover
both visible docked and visible floating frames, their transitions and hide.
