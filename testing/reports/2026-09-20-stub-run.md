## sqlite-lock / retry: mechanism changed, NEEDS-ENV

`stage03-start-sqlite-lock/retry` verified DB-error handling at session start
in August via an external `BEGIN EXCLUSIVE`. The app has since moved to
`PRAGMA journal_mode = WAL` (lib/db.ts:60): an external exclusive transaction,
`locking_mode=EXCLUSIVE` and read-only file permissions all fail to block the
app's WAL writers (verified empirically, three methods). The app code path
under test — the generic catch in `app/threshold.tsx:102` showing
«Не удалось начать молитву» with a working retry — is unchanged, but forcing
the error now needs a test hook (e.g. a debug flag that makes `enterSession`
reject). Tracked in task 86cbj95j4. The fragments stay untagged.
